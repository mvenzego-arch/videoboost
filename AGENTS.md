# VideoBoost — правила проектной команды

Проект: Python 3.10+, только стандартная библиотека. `main.py` — tkinter-интерфейс, `engine.py` — пайплайн FFmpeg/Real-ESRGAN/RIFE. Стиль UI — тёмное «жидкое стекло», палитра и виджеты в main.py.

## Автоконвейер для новых фич

Получая запрос на новую фичу, основной агент сам делегирует работу суб-агентам — от пользователя не требуется называть агентов. Порядок такой:

1. **`ux-designer`** — спека интерфейса (если фича видна в UI). Спека показывается пользователю на утверждение — контрольная точка.
2. **`visual-prompter`** — промты для графики, если фиче нужны баннеры, иконки, иллюстрации.
3. После утверждения спеки — **`ui-dev`** (main.py) и/или **`engine-dev`** (engine.py), код по спеке.
4. **`ui-copywriter`** — тексты новых виджетов (подписи, подсказки, ошибки).
5. Параллельно: **`test-writer`** (unittest в `tests\`) и **`code-reviewer`** (ревью диффа).
6. **`docs-writer`** — дополнение README/changelog.
7. Финальная контрольная точка: пользователь проверяет на своём видео.

Основной агент не правит файлы сам, если есть профильный агент для этой зоны. Промежуточные результаты передаются следующему агенту прямо в тексте задачи.

## Баги

Запрос об ошибке: сначала **`vision-triage`** (если есть скриншот — он перепишет ошибку дословно и опишет дефекты), затем **`debugger`** (диагноз), затем минимальный фикс профильным код-агентом (`ui-dev` или `engine-dev`), затем `test-writer` на регрессию и `code-reviewer` на дифф.

## Расширения конвейера

- После работы `test-writer` запускается **`qa-runner`**: он гоняет весь suite и разбирает падения. Ревью чистое + suite зелёный → доки.
- Перед выкладкой версии `release-keeper` тянет **`smoke-tester`** (старт окна, dry-run, журналы) и `perf-guardian` — тройная проверка перед сдачей.
- Смоук-тест может на секунду показать окно программы на экране — это нормально.
- Правки в `engine.py`, меняющие tile, пайплайн или кодировщик → после `code-reviewer` проверка `perf-guardian` (VRAM/время на слабом железе).
- Готовность выложить версию → **`release-keeper`** (сборка exe, чеклист, ссылки на инструменты).
- Вопросы владельца «объясни, что тут происходит» → **`explainer`**, файлы не трогает.

## Жёсткие правила (для всех агентов)

- **Язык и стек зафиксированы: Python 3.10 + tkinter, только стандартная библиотека.** Агенты не переписывают код на другие языки и не переводят UI на другие фреймворки. Запрос вида «перепиши на C#/Electron/лучший язык» сначала разбирается с владельцем: расчёт объёма переписывания, рисков, потери «нулевых зависимостей» — и только явное «да» владельца меняет стек.
- Только стандартная библиотека Python. Никаких новых зависимостей без явного решения владельца (учитывать влияние на «программа ничего не устанавливает»).
- Пути через `pathlib.Path` (кириллица и пробелы в путях — норма).
- GUI не блокируется: долгое — в потоках, виджеты трогает только главный поток через `after()`.
- Любая ошибка пользователя видна в журнале и не убивает окно.
- Прогресс длительных операций — в журнале и на полосе прогресса.
