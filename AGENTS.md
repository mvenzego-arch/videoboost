# StaticSite — правила команды проекта (E:\прога\сайт)

Проект: статический сайт владельца. Разметка + стили + чистый JS.
Никакого npm, никаких фреймворков и сборщиков. Всё бесплатно.

## Стек (закреплён решением владельца)

- **Разметка:** семантический HTML5 (`header/main/section/nav/footer`), один `<h1>` на страницу,
  `alt` у всех картинок. Один `<h1>`, а порядок подзаголовков — по иерархии h2→h3.
- **Стили:** чистый CSS3 — `css/style.css` плюс модули по необходимости. Дизайн-токены — CSS-переменные
  в `:root` (палитра, отступы, радиусы). Мобильная адаптация со стратегией mobile-first,
  фиксированные точки: 360, 768, 1024, 1440.
- **Скрипты:** vanilla JS (ES2020+) — `js/main.js` (+: модули по необходимости), без jQuery/Bootstrap/Tailwind/CDN.
- **Инструменты разработчика:** Python 3.10 stdlib — скрипты проверок в `tools/` (HTML, ссылки, веса).
  Локальный просмотр: `python -m http.server 8000` (работает из любой папки).
- **Хостинг:** GitHub Pages с корня ветки `master`. Домен — если позже появится решение владельца.
- **Кодировка:** UTF-8 без BOM. Пути — только относительные (`./css/style.css`), чтобы сайт из
  Pages и с диска открывался одинаково.
- **Браузерная поддержка:** свежие Chrome/Edge/Firefox; интернет-эксплорер не поддерживается.

## Автоконвейер для новых страниц и фич

Основной агент сам делегирует суб-агентам; владельцу не нужно знать имена.

1. `ux-designer` — спека страницы или фичи (структура секций, состояния, акту Behaviour mobile/desktop).
   **Контрольная точка:** утверждение спеки владельцем.
2. `visual-prompter` — промты графики, если нужны иконки/иллюстрации.
3. После «да» — `ui-dev` (HTML/CSS/JS) параллельно с `content-writer` (тексты страницы).
4. Затем `ui-copywriter` (микротексты кнопок/ошибок) и `seo-specialist` (title/desc/OG/sitemap/schema.org).
5. `test-writer` → `qa-runner`; в `a11y` — accessibility-auditor (контрасты, aria, фокус).
6. `perf-guardian` — б三角腰 весов: любые добавленные картинки/модилки;
   `code-reviewer` — финальное ревью диффов.
7. `docs-writer` — обновление README.
8. **Контрольная точка:** владелец открывает сайт через `python -m http.server 8000` и утверждает вид.

## Баги

Скриншот → `vision-triage` (дословно описывает видимое) → `debugger` (диагноз + доказательство)
→ точечный фикс `ui-dev` → регресс-скрипт в `tools/` → `code-reviewer`.

## Производительность (гейты)

perf-guardian подключается всегда, когда: новые/изменённые картинки, новые внешние зависимости
(какой-нибудь ещё font), изменения макетов выше «среднего».

## Что запрещено без явного решения владельца

- Фреймворки (Bootstrap, Tailwind) и сборщики (npm, webpack, Vite).
- Внешние CDN-библиотеки и шрифты (Google Fonts может не открыться; только системные стеки шрифтов).
- Аналитика, трекеры, куки и формы на чужие сервисы (нет бэкенда = формы только mailto).
- Платные хостинги, домены и платные API.

## Жёсткие правила

- Работают постепенно: страница сначала работает полностью без JS, потом JS добавляет поведение.
- Картинки: веб-форматы (WebP/AVIF при наличии), `loading="lazy"` для нижних, у каждого осмысленный alt.
- HTML обязан быть валиден: `python tools/check_html.py` зелёный перед сдачей.
- Ссылки честные: `python tools/check_links.py` зелёный (все локальные существующие, пустых href нет).
- Веса честные: `python tools/check_weights.py` зелёный (страница ≤ 400 КБ без картинок, картинка ≤ 200 КБ).
- Контрасты: основного текста 4.5:1, крупного заголовка 3:1.
- Все изменения HTML/CSS/JS коммитятся отдельными осмысленными сообщениями:
  `site: <что сделал кратко>`.
- Правки всегда точечные. Рефакторинг — отдельный тикет, не внутри фичи.
